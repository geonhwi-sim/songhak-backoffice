## 2026-11-02 · 로그인: FastAPI 자체 로그인 + HttpOnly 쿠키

- 결정: 이메일과 비밀번호(해시 저장)로 FastAPI가 직접 로그인을 처리하고, 서명한 토큰을 HttpOnly·Secure·SameSite 쿠키로 준다. 권한은 API에서 역할(owner/staff)로 막는다. 계정은 사장님 1개와 데모 1개로 시작하고, 직원 계정(U4)은 5주차에 붙인다.
- 대안: Firebase Authentication (기존 앱과 같은 방식), NextAuth
- 이유: 대시보드 데이터는 모두 FastAPI를 거치므로 권한 검사도 한 곳에 둔다. 외부 인증 서비스 없이 배포할 수 있고, 데모 DB와 운영 DB에 같은 방식을 쓴다. 토큰을 쿠키에 두면 화면 코드(JavaScript)에서 읽을 수 없다.
- 구현(2026-11-05): 비밀번호는 표준 라이브러리 scrypt로 해시, 토큰은 JWT(HS256, 12시간). 없는 이메일도 같은 시간·같은 메시지로 실패하게 해서 가입 여부를 알 수 없게 했다. 같은 이메일 5회 실패 시 10분 잠금(서버 1대 전제, 메모리 기록). 비활성 계정은 이미 받은 토큰도 바로 막힌다. 계정은 `python -m app.users`로 만든다.

## 2026-11-02 · 자연어 질의 안전장치: 뷰 전용 읽기 계정, 복잡한 규칙은 계산 결과로

- 결정: 질의용 `qa` 스키마에 뷰 6개(정산처, 정산 항목, 근무 기록, 급여, 발주, 발주 품목)를 두고, 이 뷰의 SELECT만 가진 계정으로 SQL을 실행한다. 계정 기본값은 읽기 전용 트랜잭션, 실행 5초, search_path = qa. 결과는 200행까지만 읽는다.
- 주휴수당처럼 규칙이 복잡한 값은 SQL로 다시 계산하게 하지 않는다. 파이썬 계산 결과를 `payroll_periods`에 저장하고(가져오기 때마다 다시 만듦) 뷰로 보여 준다.
- 대안: 원본 테이블 전체를 읽게 하고 프롬프트로 제한, LLM이 주휴 규칙을 SQL로 계산
- 이유: 프롬프트는 우회될 수 있지만 DB 권한은 우회할 수 없다. 원본 테이블에는 지운 주문, 원본 ID 같은 혼동 요소가 많아 뷰에서 미리 정리하면 정답률도 오른다. 주휴 전환 규칙은 사람도 틀렸던 계산이라 한 곳(app/payroll.py)에서만 계산한다.
- 확인: 원본 테이블 조회, 뷰 쓰기, 임시 테이블, 5초 초과 쿼리가 모두 막힌다. 급여 뷰의 7~10월 합계가 지급액과 같다.
- 함께 고친 것: 근무가 없는 급여 기간에도 지난 주의 주휴수당이 들어갈 수 있는데(일요일이 다음 기간인 주), 인건비 API가 그 기간을 빼고 있었다. 실데이터에는 아직 해당 사례가 없다.

## 2026-11-02 · 평가 세트: 정답은 값이 아니라 정답 SQL

- 결정: 20문항(정산 8, 인건비 6, 발주 4, 복합 2, 이 중 1문항은 데이터 없음)에 정답 SQL을 붙이고, 채점할 때 정답 SQL을 실행한 결과와 비교한다. 행 수가 같고 정답 값이 답 행에 모두 들어 있으면 맞다.
- 이유: 공개 저장소에 실제 금액을 두지 않으면서, 데이터가 늘어도 평가 세트를 고칠 필요가 없다. 동점 때문에 정답이 흔들리는 "상위 N개" 문항은 바꿨다.
- 한계: 발주 데이터가 아직 1건이라 발주 문항은 변별력이 낮다. 데모 DB(4주차)에서 한 번 더 잰다.

## 2026-11-05 · 자연어 질의 에이전트: LangGraph 4단계, 첫 평가 20/20

- 구조: SQL 쓰기 → 실행 → (실패하면 오류를 보여 주고 다시 쓰기, 2회까지) → 답변. 뷰로 답할 수 없는 질문은 SQL을 실행하지 않고 이유를 말한다. 3번 모두 실패하면 "답을 찾지 못했다"로 끝난다.
- 모델: Claude Opus 5.5. SQL 쓰기는 effort medium + 구조화 출력(SqlDraft), 답변은 effort low. 스키마 설명은 DB의 뷰·열 주석에서 읽어 시스템 프롬프트에 넣고 캐시한다(뷰를 바꾸면 프롬프트도 따라 바뀜). 오늘 날짜와 질문은 사용자 메시지로 보내 캐시를 깨지 않는다.
- 평가(오늘 날짜를 11/5로 고정): 1회차 19/20. 틀린 1문항은 "2025년 12월 정산"에 `COALESCE(sum, 0)`을 써서 "데이터 없음"을 "0원"으로 답한 것. 합계에 COALESCE를 쓰지 않는 규칙을 넣었다. 답변 문장에 "실제 정산 금액과 다를 수 있다" 같은 근거 없는 단서가 붙어, 답변 단계에도 도메인 규칙을 넘겼다. 최종 20/20, 숫자 하나가 정답인 11문항 모두 답변 문장에 정답 숫자가 들어 있음. 문항당 약 5초, 20문항 약 0.36달러.
- 한계: 평가 결과를 보고 프롬프트를 고쳤으므로 20/20은 이 세트에 맞춰진 점수다. 처음 보는 질문으로 다시 재야 한다(실사용 질문을 모아 2차 평가 세트로). 발주 데이터가 1건뿐이다.
